## Repository map

The package has four main skill families plus core and host guidance:

| Area | Responsibility | Main overlap risk |
| --- | --- | --- |
| `engineering-*` | architecture, implementation, infrastructure, data, integrations | broad roles can overlap domain specialists |
| `security-*` | application, cloud, credential, threat, compliance, incident security | AppSec, security architecture, and AI-code auditing can all claim code review |
| `testing-*` | automation, API, performance, accessibility, evidence, workflow validation | test automation, reality checking, and evidence collection can duplicate verification |
| `design-*` | UI, UX, brand, accessibility-oriented visuals, finish review | UI designer and finish reviewer can overlap implementation review |
| `antigravity-superpowers` | orchestration and cross-family routing | previously attempted to activate all installed capabilities |
| `antigravity-guide` / SDK | host guidance and integration reference | can become stale when host capabilities change |

The repository also contains a checked-in `.agents/skills` mirror of `skills`, installer logic that copies `skills` into local and global Gemini locations, privacy tooling, plugin definitions, and a Bun CLI.

## Routing behavior found

The previous core instruction explicitly said all installed skills, MCP tools, subagents, and routers should be used on every task. That made over-routing the default behavior and contradicted the intended minimal workflow.

The core prompt also referenced `agency-*` skill names even though the repository exposes `engineering-*`, `security-*`, `testing-*`, and `design-*` names. The division router used the real names, leaving two conflicting sources of truth.

Host assumptions were also too strong. The core required `invoke_subagent` without first proving that the active Antigravity or Gemini CLI host exposed it.

## Initiative selected

**Minimal deterministic routing contract + scenario evaluations**

Why selected:

- fixes a direct contradiction in current behavior
- reduces unnecessary context and specialist activation
- creates deterministic regression coverage
- exposes an explainable `route` CLI for debugging routing decisions
- corrects stale skill names in the core prompt
- allows later host adapters to share one routing policy instead of duplicating heuristics

## Implemented in this run

- added `src/routing/router.ts`
- added scenario-based Bun tests including over-routing regressions
- added `antigravity-superpowers route <task>`
- rewrote the core routing instructions around minimal, capability-aware selection
- synchronized the checked-in `.agents` core skill mirror
- added GitHub Actions CI for tests, privacy checking, and routing CLI smoke testing

## Known limitations

The router is intentionally conservative and deterministic. It does not yet read every individual skill's frontmatter or dynamically rank all installed specialists. That should follow only after skill metadata is validated and overlap boundaries are made machine-readable.

The checked-in `.agents/skills` mirror remains a drift risk. This run synchronizes the core skill but does not redesign the packaging layout.

The installer and privacy dynamizer still contain independent reliability and safety work that should be handled as separate initiatives with their own regression tests.
